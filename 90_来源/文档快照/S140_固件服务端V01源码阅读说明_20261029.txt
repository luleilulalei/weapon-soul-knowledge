# 器灵 Spirit V0.1：基于 Usaki 的固件与服务端适配

这是实际修改后的源代码，不是只有接口描述的方案。复用用户提供的 Usaki ESP-IDF 固件和 Python 服务端，面向 V0.7.2 电气连接。**尚未上板验证，不是量产发布包。**

## 从哪里开始

- `firmware/README_SPIRIT.md`：ESP-IDF 版本、构建命令、GPIO、按键操作、隐私与实现边界。
- `firmware/src/spirit_peripherals/README.md`：新增外设的具体实现、校准和限制。
- `server/README_SPIRIT.md`：服务端启动、开发协议、离线测试与安全边界。
- `VALIDATION.md`：本次实际做过什么测试，以及没有做过什么。
- `CHANGE_REPORT.md`：相对两个原始压缩包的文件级变更清单。
- `MANIFEST.json`：交付文件的 SHA-256，可用于检查文件完整性。

## 这版做了什么

1. 双屏改为一个 GC9A01，保留 Usaki 原有动画实现，并替换器灵 GPIO。
2. 双麦路径替换为一个 PDM 麦，复用原有 Opus、语音协议和功放播放链路。默认采用手动起止、轮流说话，不宣称远场全双工。
3. 原舵机、PCA9685、MPR121 等兔子硬件路径退出当前构建/启动流程；保留的历史源码不代表当前设备具备相应能力。
4. 新增 BMI270 官方初始化与原始六轴采样、CAP1296 六通道触摸、TCA9534 状态读取。
5. 新增电池 ADC 校准读取与电压估算，依据 R124/R125 均为 100kΩ 使用标称 2:1 分压。不伪造电量百分比。
6. 新增 DRV2605L 受控驱动、共享升压供电管理；马达默认关闭，必须配置正确参数才能触发。
7. 新增可选 PN532 查询与 UID 读取。UID 不等于防伪认证，默认不开启未确认的 NFC 模块。
8. 新增 J7 独立 I²C 安全门控和受限传输入口；**剑身从控协议未提供，不能承诺已经能控制真实剑身灯效**。
9. 新增 Spirit 设备状态/效果开发通道，保留原语音链路；拒绝不支持的指令，不把未执行当成功。
10. 软件静音持久化、默认静音、队列与过期音频处理；不能冒充麦克风物理断电。

## 首次使用顺序

先阅读两端 README 和验证报告。安装指定 SDK/依赖，在本地配置自己的网络和服务地址，然后编译。先验证电源和板级接线，再逐项启用外设；不要直接把所有可选功能打开后一次性上电。固件未设置凭据时以本地模式启动，不会使用原附件中的私有账号连接服务。

首次固件默认麦克风静音；当前交互约定为主键长按约 1.5 秒切换软件静音，取消静音后短按开始/结束一轮语音。它是本版实现约定，不代表最终产品交互已冻结。

**J7 必须断电插拔；GPIO8 是共享 5V 升压使能，不是整机电源键。**

## 不在本版完成范围

Unity BLE GATT、成熟姿态融合/剑技识别、完整剑身协议与配件从控固件、NFC 安全签发核销、生产鉴权、完整 OTA 下载/签名/回滚流程、低功耗产品策略、声学调优和实物可靠性测试，均不能据这次源码交付视为完成。部分基础设施/预留配置是否存在，以对应 README 和验证报告为准。

## 凭据与数据

交付包不包含原 `.env`、个人运行记忆、数据库或网络密码配置。请在自己环境里填入配置；不要把生成的 `sdkconfig` 或 `.env` 发到公共仓库。原附件中的真实凭据未用于本次测试。当前开发服务默认仅用于可信隔离局域网，不能直接裸露到公网。

本次没有推送 GitHub、部署服务或烧录设备。没有替用户冻结新版 PCB。附件中的原始代码包另行保留，此包是适配后的独立版本。
