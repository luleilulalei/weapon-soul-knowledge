# 器灵 · 非触摸显示屏补充修订

版本 R2（V1.4） · 2026-10-18 · 适用：实体圆屏、输入分工及相关 PRD

## 1. 本次裁决与适用顺序

最新明确要求：“屏幕交互你怎么做的还是触摸屏，整的跟手表似的，不要这样，屏幕不带这种交互”。本修订据此明确：器灵屏幕是表情与状态的显示输出，不是触摸屏，也不是靠实体键逐项浏览的手表菜单。

本修订覆盖旧稿中与该要求冲突的描述和图示；其余已确认能力与业务约束继续有效。旧版文档、图片和打包文件保留作追溯，不再作为实体菜单的实现依据。本版在非触摸显示边界之上落实记忆与对话范围；不新增硬件或设置项。

2026-10-18 最新确认：“记忆 允许查看、删除 但是不允许修改，还有闯关的记忆不需要支持 是否保留记忆这种操作，还有游戏端不需要支持对话，只在硬件侧能和器灵进行对话即可”。因此，既有记忆只可查看、删除；删除记忆更正流程；闯关不出现保留/舍弃记忆的询问、选择或开关；器灵对话仅在硬件侧。本修订不决定闯关记忆是否自动保存、生成或保留。

### 1.1 已确认边界

- 屏幕：只输出眼睛、表情、必要图标及简短当前反馈。不放点击按钮、滑动提示、分页点、选择焦点、列表、返回入口或参数调节器。
- 独立触摸区：屏幕周边壳体与握持区均保留触摸互动要求（Q73/Q134、HW-010）。触摸区域不是显示玻璃，不能以屏幕上的坐标或图标位置作为输入。
- 实体按键：保留电源、深度休眠唤醒和非语音采音控制的已确认职责（Q08/Q97/Q135、HW-008/009）。不确定按键数量、结构、精确位置或按法，也不新增独立隐私开关。
- 已有输入：麦克风用于允许状态下的语音；IMU 用于已确认体感；背面 NFC 区用于读卡；底座及充电连接产生实际状态事件。圆屏不参与上述输入采集。
- 手机 App：保持已确认横屏方案，承担列表、选择、文本输入、详细设置与审批说明。手机上的触屏控件继续有效；记忆管理仅查看与删除，游戏 App 不承载器灵对话。

### 1.2 设计提案与待验证

- 本稿的表情、短文案和布局为修订设计；不把样张等同于设备已有实现。240×240 是沿用评审画布，不锁定屏幕物理尺寸。
- 实体按法、触摸手势和区域边界、输入消歧、主人权限、重启隐私保持、远距停局和安全关断信号仍须对应 D05/K03、D07、D09 评审与实测。
- 废止旧候选 A/B 中“长按开菜单→短按循环→再次长按确认”的整条路径；不把它换成触摸区滑动导航，也不将旧双击/短按语义升格为已批准。
- App 承接复杂设置不等于取消无手机完整联网对话和已有离线能力；不强制每次唤醒、触摸回应或练习都先开 App。

## 2. 误导审查与替代依据

### 2.1 必须废止的菜单机制

- 横屏包《UI行为与验收补充》UIR-030、device/screens.md 第7节、《改版决策记录》K03：旧稿虽声称不增加触屏，仍以圆屏焦点、循环选择和确认菜单作为操作中心。改为“实体直接输入职责及状态反馈”；不保留菜单候选 A/B。
- 横屏包“模块PRD_V1.3”中 01_实体光剑硬件的 UIR-030 全文、11_需求决策记录的 K03：上述冲突已被复制，适用同一替代，不得从副本恢复旧按法。
- 扩展包 device/spec.md 第2—4、6节，及《交互补图与PRD承接》第5节、X-D01—08索引、EXT-T07/08：菜单进入、选项高亮、释放门槛、二次长按、超时退出均不再作为产品流程。保留隐私权限、请求与真实结果分离等安全要求，但删除它们对菜单的依赖。
- X-D_01“单键菜单与独立确认”及 X-D01—08 原图：原图即使不是触屏，也呈现手表式导航。此次替换仅保留 ID 追踪，不能据这些 ID 推导新菜单或强制八步流程。

### 2.2 必须澄清的表达

- 原 PRD 00 的“屏幕、触摸、按键”并列，01 HW-002/HW-010、02 的触摸表情说明：补“显示面与独立壳体触摸区分离”。这些原文不构成触摸屏需求；不得删除触摸已确认功能。
- D21—D24/M01 只用于硬件对话中新记忆的许可与保存，不得复用于闯关记忆保留/舍弃。D25/M02 已由原更正流程替换为只读查阅；D26—D28/M03 保留删除确认、执行与结果核对。所有屏内画面仅反馈状态，均无可点选确认/取消。
- 硬件联动稿第3节的“触屏暂停”以及 UIR-057、游戏 PRD 与原型追踪中同义文字：均应明确为“手机 App 触屏暂停”。不能误读为实体圆屏，也不能把它当远距即时停局方案。
- 离线演示、可点击画廊及输入模拟：控制按钮必须处于硬件轮廓之外，标为评审模拟；点击圆屏不得触发产品操作。画廊放大图片只是查看资产。
- 总视觉/组件规范的触区、侧栏、返回、列表等仅用于手机 App，不得自动套用到圆屏。

### 2.3 继续有效的规则

真实采音标记、等待与完成区分、取消旧输出、入座结束旧局、充电禁挥剑、离线练习不成长、NFC读到不等于解锁、关机完成后才可拆装均保留。旧 X-D09—16 的安全事实可复用，但界面需去除任何菜单残留。

## 3. 功能分工：陪伴、隐私与记忆

以下逐项规定“显示什么、从哪里输入、App 做什么、如何验收”。能力确认不代表具体输入映射已冻结。

### F01 日常陪伴与对话 · 已确认能力，反馈为设计提案

- 显示：待机眼神、被叫到抬眼、聆听、思考、说话、结束；持续保留真实采音状态。无屏内输入入口。
- 输入：有效唤醒与话语进入麦克风；仅在真实采音允许、相应模式可用时处理。取消/打断按已有获批渠道，不预设新按法。
- App：命名、联网及详细设置，不提供器灵聊天入口、对话输入或发送操作。对话仅在硬件侧；设备有网而 App 未打开时仍能完整对话。
- 验收：触碰显示面不唤醒、不确认、不切状态；网络断开、服务失败、取消后迟到回答不冒充成功或续播。

### F02 独立触摸安抚与回应 · 保留 Q73/Q134

- 显示：短表情回应，如开心眼，随后回当前状态；关麦标记持续存在。
- 输入：屏幕周边壳体或握持区的有意触摸；真实区域、有效手势与误触策略待 D05。不得把用户必须触摸的目标画在屏内。
- App：如需解释触摸能力，在使用说明中标注实际壳体区域；不新增配置页或取消既有功能控制方向。具体功能控制映射未定时不暗示已经支持。
- 验收：分别覆盖显示面触碰、周边触摸、握持触摸、普通握持与挥剑。只有获批独立输入产生相应反馈；不误开麦、不改资产、不切模式。

### F03 关闭与恢复采音 · 已确认职责，实体按法待定

- 显示：正在核对、真实已关闭、真实开启或状态未知；仅真实停止全部采集后显示“麦克风关闭”。不开菜单，不显示开关按钮。
- 输入：复用实体按键的明确非语音操作，恢复还须有效权限。具体短按/双击/长按及阈值不在本稿确定；普通触摸、名字、入离座与唤醒不恢复采音。
- App：显示当前或上次已知状态、解释获批操作；沿用不提供远程开麦的当前提案，不新增远程控制作为替代。
- 验收：请求提交、实际停采、实际恢复三者分开；延迟、失败、未知均不假报。关麦时对话唤醒无效，表情和允许的战斗仍可用。

### F04 记忆查看与删除 及硬件对话新记忆

- 显示：D25/M02 仅反馈查阅定位与只读内容；D26—D28/M03 反馈删除确认、执行中、完成或未完成。圆屏不显示私人内容列表、编辑入口、确认按钮或菜单。
- 输入：查阅、删除须先确认身份、权限与唯一目标；通过获批硬件语音或 App 的只读详情/删除操作完成。目标模糊先澄清；沉默、普通触摸和表情回应均不是删除许可。
- App：既有记忆只允许查看与删除；取消更正、编辑、重写、覆盖保存能力。删除确认应说明对象与影响，执行结果未知或部分完成时不显示全量完成。
- 新记忆：D21—D24/M01 仅承接硬件对话中新记忆的既有许可与保存反馈，不修改已有记忆，不提供修改成功状态。许可不等于实际写入成功。
- 闯关记忆：不出现是否保留、保留/舍弃选择或保留开关；不把 D21 等硬件对话许可状态复用于闯关。是否自动生成、保存或保留闯关记忆，不由这次 UI 修订确定。
- 验收：只读查阅不能提交内容变更；两条相近记忆不会选错；删除须独立明确确认，部分清理不显示全部删除；失去权限不展示或读出私人内容。游戏端没有器灵对话输入/发送链路，硬件对话保留。

## 4. 功能分工：动作、电源及系统

### F05 自由挥剑与战斗 · 已确认能力，参数待验证

- 显示：专注眼、当前技能的收到/就绪/成功/取消短反馈；灯声震承担动态反馈，不要求挥剑时读圆屏或操作圆屏。
- 输入：IMU 及获批动作判定；触摸显示面无战斗作用。输入收到与命中裁决不是同一事件。
- App：选择训练/技能、教学、安全准备、详细 HUD 与结算；沿用抬起/举高蓄势→就绪→向下挥斩的当前方案，姿态阈值不在本稿重定。
- 验收：单次有效动作不重复计分，取消后不补播旧效果；圆屏显示失败不制造命中。

### F06 本地练习及暂停 · 能力保留，远距停局未关闭

- 显示：准备、练习中、动作收到、当次评分、停止待确认/已停止。停止请求未被接受前不显示已暂停。
- 输入：允许采音时的已支持本地指令及体感；关麦时的独立非语音停局仍需 K03/D07 解决，不能用圆屏菜单冒充完成。
- App：联网训练的手机触屏暂停与恢复准备；靠近手机前先停止挥动、置于安全状态。不得以手机暂停入口要求用户持剑奔向手机。
- 验收：关麦、无手机和离线场景逐项检查可安全停止路径；未获批路径作为实机放行阻断。离线评分不增加或补发长期成长。

### F07 电源与浅/深眠 · 已确认职责，具体动作待定

- 显示：入眠表情、唤醒就绪、关机进行中或未确认。深眠持续显示能力不作承诺；黑屏不能证明安全断电。
- 输入：实体按键承担电源和深眠唤醒；浅眠语音唤醒受真实采音状态约束；自动休眠由获批条件触发。无需进入屏内菜单。
- App：提供使用说明与状态解释，不新增手机远程开关机。按键数量和操作时长仍待硬件交互评审。
- 验收：一次实际输入仅有一个语义结果；唤醒不顺带开麦，残留事件不重开机；未确认安全关断不引导拆装。

### F08 底座、充电与剑身 · 已确认能力

- 显示：入座结束、陪伴、充电、未充上、当前形态或识别未知。屏幕只是实际状态输出。
- 输入：底座/充电实际事件；仅安全关机后装卸剑身，再开机识别。输入不来自点选屏内图标。
- App：退出结算、形态与连接详情、异常说明；离座不恢复旧局，仍连接充电则继续禁止挥剑。
- 验收：入座抖动不重复结算，充电不等于入座，未知形态不沿用旧属性；完全断电后不承诺屏幕还能显示完成画面。

### F09 NFC 卡牌 · 已确认读卡，权益政策沿用 D03

- 显示：读到、核对中、结果反馈；不画卡牌列表或“兑换”按钮。
- 输入：卡牌靠近背面 NFC 区；用户在安全静止状态操作。读到卡不等于已经消费。
- App：目标器灵选择、权益详情、消费确认、未知结果核对与装饰启用；不把选目标迁回设备屏幕。
- 验收：读到未裁决不庆祝解锁；重复读取、失败、断连与原目标保持一致。

### F10 首用、设置与账号 · App 承接复杂流程

- 显示：待连接、核对中、连接状态和简短结果；必要设备识别图形只能供辨认，不供触摸选择。
- 输入：手机 App 操作和相应已获批实体确认；具体实体确认动作未定时不编造按钮或按法。
- App：现有发现/主人确认/联网/命名，以及 A05、X-A00—12 的账号、授权、诊断、说明等原有范围。X-A09“声音与显示”仍只调手机 App，不借此新增设备亮度、音量或远程开麦。
- 验收：普通连接不授予主人权限；离线旧状态有明确标识；未确认授权不开放私密内容。

### F11 低电、安全与故障 · 已确认方向，阈值及回退待验证

- 显示：单一最重要原因与停止/限制反馈，同时保留真实隐私标记；不用错误菜单要求逐层退出。
- 输入：设备真实分级事件；处理动作遵从获批安全说明。屏内触碰、普通按键或触摸不能解除保护。
- App：详细原因和处理说明，不把刷新当修复或重新开战。缺少可靠显示时，仅采用实际存在并验证的声/灯等渠道。
- 验收：未知不画安全成功；故障解除不自动续战或恢复采音；无可靠安全反馈的操作不放行。

## 5. 显示与原型的统一约束

### 5.1 画面层级

眼睛/表情为主体，叠加必要的采音事实和当前单一反馈。普通状态避免两行以上解释；复杂说明写到画外评审注释、语音或手机 App。危险状态可优先显示原因与停止提示，但不遮掉真实采音事实。此处为视觉目标，字数及实际可读性以样机验证，不以增加小字解决信息过载。

状态环仅表达实际处理或动作进度，不表现“长按确认进度”。图标不带按钮底座、按压态或可点击焦点。不用手指按屏、滑动箭头、列表滚动及分页圆点。表情变化不能暗示已授权、已保存、已停采或安全已关断。

### 5.2 输入与反馈证据链

真实输入位置 → 当前权限与模式 → 有效请求 → 实际执行事实 → 圆屏/声/灯/震反馈。操作发起与成功反馈分别记录；不以动画结束或固定延时替代完成信号。取消、入座、隐私变更与模式结束使过期输出失效，不吞掉先前已合法完成的结果。

原型所有“模拟输入/成功/失败”仅在画外评审控制区；设备显示面无业务点击、滑动或菜单导航事件。硬件结构图须分别标“仅显示圆屏”“独立壳体触摸区”“实体按键（示意）”，区域和位置不能冒充工业设计定稿。

### 5.3 画面编号承接

保留 D01—D44 与 M01—M06 共50帧，按上述规则修正表达。X-D01—X-D16 保留追踪编号，其中原 X-D01—08 的导航含义作废，改为单一状态示例；X-D09—16 继续区分请求、真实结果与条件性安全完成。全部66帧是可复用状态资产，不是66个产品页面或菜单层级。

## 6. 验收、待决与交付门槛

### 6.1 修订稿检查

- R-T01：逐张检查66帧与硬件图板，无触屏按钮、焦点、列表、滑动提示、分页或屏内按键操作指令；手机 App 控件不在此禁令范围。
- R-T02：检索当前修订规范和原型；旧菜单按法仅允许出现在明确“废止”的追溯段，不能仍是默认推荐。
- R-T03：圆屏区域的点击、长按、拖动与滑动均不触发业务；画外模拟操作明确说明输入源，不冒充硬件识别。
- R-T04：对每项 F01—F11 核对显示、真实输入、App 承接及状态依据。App 没有新增远程开麦、未确认设备设置或账户能力。
