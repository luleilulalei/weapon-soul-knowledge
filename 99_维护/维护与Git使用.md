# 维护与Git使用

本仓库是器灵的可携带项目记录。Git保存修改历史，不会自动把内容写入聊天记忆，也不会自动同步另一台电脑。

## 日常更新

1. 阅读MEMORY.md与当前基线，定位对应主题。
2. 新结论记录来源和日期，区分用户决定、提案、工程实现与实测。
3. 如果替代旧要求，更新决策台账和历史替代关系；保留原始证据。
4. 保存新增证据快照及SHA-256，更新来源清单。内容相同复用已有快照；旧证据不覆盖。
5. 更新MEMORY.md和更新记录，运行校验，再检查差异并提交。

## 常用命令

在仓库目录执行：

```sh
git status --short
git diff
python3 tools/verify.py
git add -- 明确修改的文件
git commit -m 'docs: 说明本次决定或进展'
git log --oneline -8
```

`git add`一行中的“明确修改的文件”需替换为实际路径。只提交相关文档，不默认把整个父目录、安装包、缓存或敏感信息加入版本库。

需要检查原目录是否已变化时使用 `python3 tools/verify.py --check-originals`。文本证据丢失或校验不一致会失败；新电脑缺少原绝对路径时会报告来源不可用，仓库内文本快照仍可阅读。

## 跨电脑和云端接续

当前没有远程仓库。后续可选择私有Git仓库，将本仓库推送后在另一台电脑克隆；工程附件另行同步。远程地址和平台尚未指定，本次未创建或推送。

在新聊天中明确提供本仓库目录，先读MEMORY.md、当前基线和相关主题。只使用云端聊天时，可提供MEMORY.md及需要的主题文档；如果上传静态副本，应带更新日期，更新后重新同步。保存文件本身不保证任何聊天会自动读取。

## 证据维护

`90_来源/文档快照/`保留旧文档原字节。原文的相对图片或附件链接可能指向原始包，不要求在证据目录内重写。校验工具检查当前整理文档链接、证据完整性、索引和Git意外大文件；它不验证电子电路正确性或产品合规性。
