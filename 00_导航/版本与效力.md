# 版本与效力

同一项目同时有需求版本、角色版本、硬件版本、机械版本和软件版本。编号只在各自领域内比较，不能用“V1.5最大”覆盖所有工程事实。

## 判断顺序

1. 用户后续明确决定，按其实际范围替代旧决定。
2. 对应该决定的专项修订和可核对工程交付。
3. 不冲突的旧PRD与验收规则。
4. 已标注提案的设计内容，用于评审与原型。
5. 历史助手建议、旧截图和模拟演示，用于追溯。

“已确认”描述用户要什么；“已实现”描述源码或工程已有内容；“已验证”必须说明在哪个环境验证了什么。三个状态不互相替代。

## 各版本的作用

| 版本 | 用途 | 不能据此推导 |
|---|---|---|
| PRD V1.3与非触屏修订 | 业务规则、横屏UI、身份、异常与验收基础 | 旧聊天、记忆更正、旧屏菜单仍有效 |
| PRD V1.4专项 | 对话端、记忆只读删除、结算移除记忆选择 | 所有关卡已获准自动写长期记忆 |
| PRD V1.5提案 | 两产品世界、剧情、玩法与内容预算 | 十二关、自动记忆数值、奖励已冻结或实现 |
| 角色V1.0 | 用户新确认角色方向后的详细创作稿 | 旧ENFP/ISTJ或旧儿童化形象仍需保留 |
| PCB V0.7.1及后续变更记录 | 追溯电源、麦克风、接口迭代 | 各历史局部检查是最终整板状态 |
| PCB V0.7.2 | 当前完整工程与手动布局布线交付 | 实物上电、温升、射频、整壳适配已通过 |
| 机械V0.2 | 旧选型的数字几何与试打印 | 自动兼容新屏、新LRA、NFC模块及新布局 |
| 单IMU V0.1 | 早期候选算法、协议与验收边界 | 旧GPIO和未编译说明仍代表最新Unity工程 |
| Unity训练场开发版 | 当前运行与构建记录 | 完整App、硬件链路、十二关已完成 |
