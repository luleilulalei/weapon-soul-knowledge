# 器灵游戏 UI · 全横屏状态与行为规格

日期：2026-10-18。修订：v1.4。对象：Android 单人样机的可评审高保真界面。全部状态原生重排为 844×390 横屏。

## 先看这四张板

- `boards/01_横屏大厅准备与结果`：横屏训练大厅、安全准备、普通失败、首过继续。
- `boards/02_准备与方向教学`：离屏倒计时、方向演示、尝试、纠错、成功、辨向运行。
- `boards/03_攻防与向下释放`：节拍、敌人防御、格挡窗口、蓄力、释放、取消。
- `boards/04_暂停恢复与正常结束`：普通暂停、恢复准备、断连待核对、恢复后新开。

每张板有可编辑 SVG 和使用 sharp 渲染的 2× PNG。评审说明全部在设备画面外。单屏均在 `screens/`，全部直接检视 844×390 横屏；没有拉伸旧竖屏截图。

**58 张是状态样张，不是 58 个独立开发页面。** 为离线点击原型维持关卡上下文，辨向 / 节拍 / 守门者导出了相同准备与教学模板的不同状态。实际 Unity 建议使用八套模板、一个训练场、一个敌人、三种技能数据和一个共享状态机。不得按导出 SVG 数量估算页面开发量。

本次是视觉与行为设计；没有实现 IMU 识别、真实 3D 模型、联网、生命扣减、成长或记忆保存，也没有执行用户测试、样机测试或安全验收。场景底图是可替换的概念插画，UI、指令、轨迹、生命、窗口、按钮和文字保持独立可编辑。不要把插画中的剑尖轨迹当成空间追踪能力。

## 固定边界与本轮默认

保持 PRD 04 / 07 / 09：方向与时机判定；单人、单实体；正常战斗只有简短指令；入座结束本局、离座不续局；充电禁止挥剑；离线练习不产生长期成长；未识别不补为成功；同一次动作不重复伤害；游戏端不提供器灵对话；闯关结束不设置记忆保留决定。

本轮供评审的默认值，不覆盖既有已确认规则：

1. 延用 D04 内容提案：辨向 6 次、有效至少 4 次；节拍 4 组、完整至少 3 组；守门者双方各 3 格生命，三次有效反击获胜。
2. 近屏设置完成后放稳手机，给 8 秒回站位。8 秒是可调 UI 建议，不是安全距离或识别性能标准。未完成放置确认时不启动倒计时；取消回到准备。
3. 不计分方向验证成功后，3 秒提示进入所选关卡。准备页和最终开始点再次读取器灵、授权、连接、剑身、入座、充电和风险；不能复用过期的绿色检查。
4. 正常暂停保留当前局已确认的临时进度，清空未完成组合、蓄力和待判动作；恢复经过离屏准备与不计分方向验证，再打开下一个安全提示窗口。
5. 断连、后台等中断建议先停局、核对唯一终态；本局若明确中断，无胜负、无成长，重新准备新开。此为 D07 待批方案，不能把“已连接”当成终态确认。
6. 普通失败与主动退出默认无新技能；已有技能保留。主动退出是否有其他部分奖励仍依 D01。通关、失败、主动退出、中断、结果未知不混用。
7. 首次节拍通关只授予一次蓄势斩；重复通关显示已拥有。没有货币、星级、付费复活、体力、联网对战或虚拟摇杆。

## 关键未决：远距离暂停没有被触屏按钮解决

基线是近屏设置、离屏倒计时、硬件关麦时也可完成准备、App 触屏暂停。玩家感觉不安全时应立即停下并放下剑，不需要为避免失败继续动作；接近手机前先停止挥动。按钮只是可达的操作入口，并不能保证用户站在安全挥剑位置时能即时触达。

不能声称当前方案已经完成“关麦下远距即时暂停”的安全闭环。实体按键与非语音控制映射仍是 D05 必须批准并实测的关键项，不能默默把电源键或关麦键设为开始/暂停。可比较候选为：获批非语音硬件控制；或每个完整攻防循环后自动停在安全间隙。后者增加往返操作、破坏连续节奏，本轮不作为默认。

输入姿态、动作窗口时长、识别率、延迟、唯一剑身的握持舒适性、左右手适配、手机实际阅读距离、实体灯声震强度及 Android 横屏锁定/后台行为均待实测。教学人形为单手概念动作示意，不是已验证的动作标准。

### 参数化样张后缀

`D` 为辨向，`R` 为节拍，应用于 G02 / G03 / G04 / G05 / G06 / G06U / G07 / G03T。它们和无后缀守门者共享同一教学与准备模板，只改变所选目标与最终返回位置。`S` / `C` 是守门者准备页中基础斩 / 回锋的选中状态。`U` 表示输入未知，不能解释为方向错误。

## 原型上下文与热点约定

`screens.json` 每项为 `{id,title,file,width,height,hotspots,events}`。`file` 相对本目录，`x,y,w,h` 为屏幕逻辑坐标。仅真实按钮出现在 hotspots。IMU、倒计时、条件检查、连接和结果确认都在画面外的 events 模拟，不画成实际游戏按钮。

- `gameMode`：`discern` 辨向；`rhythm` 节拍；`guardian` 守门者。默认 guardian。
- `skill`：`single` 基础斩；`combo` 回锋；`charge` 蓄势斩。默认 charge，仅在守门者使用。
- `prepareTarget`：最近明确选中的准备状态 G02D / G02R / G02 / G02S / G02C，恢复连接后保持关卡和技能。
- `setContext` 在导航前更新；`contextTarget:{key,targets}` 依据一个上下文字段覆盖 target。不同时解析两个字段，组合状态通过 prepareTarget 保存。
- 所有真实触屏暂停都到共享 G14；恢复验证成功依 resumeTarget 回 G08/G09/G10/G10H2；共享覆盖层不硬写另一关的生命和标题。
- 所有结算不连接记忆确认或记忆列表；侧栏头像 A05、App 器灵 A01、收藏 A03、训练 G01；新手/仅辨向通过的收藏接 A03N。
- 原型静态结果为预置案例，不实时计算用户点了几次。模拟事件已明确写“完成余下组合并确认通关”等条件。实现中必须以单局事件与唯一结算计算，不能照静态跳转发奖。

## 反馈语言：收到动作不等于命中

| 事件 | 屏幕 | 灯 / 音 / 震建议语义（待验证） |
|---|---|---|
| 输入收到，仍待判断 | 中性收取提示，无生命变化 | 轻短确认，不能用命中庆祝 |
| 窗口内有效斩击 | 对应目标生命仅减一次；短青蓝命中轨迹 | 一组一致的命中反馈 |
| 正确格挡 | “格挡成功”，进入反击窗口 | 独立防御确认，与受伤互斥 |
| 蓄力中 | 金色填充环 + 尚未就绪 | 渐进准备语义，不等于已获得伤害 |
| 蓄力就绪 | 大字“现在释放”，切换倒退窗口 | 单独就绪提示，可听/可感，不只靠颜色 |
| 错向 / 过早 / 过晚 | 一次只给一个有证据的原因与下一步 | 克制短纠错，不羞辱，不诱导加力 |
| 输入未知 | “动作还不清楚” | 中性提示，无错误方向推断 |
| 取消 / 暂停 / 安全抢占 | 去掉动作邀请和未完成轨迹 | 取消过期反馈；严重风险优先，具体强度未定 |

## 验收与仍未画全的部分

### 蓄势斩与实体表达统一

依据已核对的早期需求表达，本轮统一蓄势动作的细化候选为“抬起 / 举剑蓄力→就绪→向下挥斩”。实体反馈方向是从根部渐亮至整剑身，完成向下释放后恢复常态；G12/G13与结果技能说明同步。旧04/09的“持势→右斩释放”原为待批候选，本轮不继续沿用互相冲突的画面。

只有蓄势释放候选改变。基础斩仍是左斩或右斩；回锋仍是左斩→右斩。具体举剑姿态、高度、安全动作幅度、IMU判定、窗口与物理灯效同步尚未实测，不能凭动画或箭头宣称已验证。就绪前释放、离姿、超时、防御切入、暂停、断连、入座、充电与风险抢占仍取消未完成蓄力，不继承、不补打。

所有画面外说明仍与实际UI分离。按键映射未批准、远距非语音即时暂停未解决的边界保持原样，横屏重排不等于通过安全验收。


## v1.4 对话与记忆边界

- 游戏端没有文字输入、语音录入、聊天按钮或与器灵对话入口。器灵对话仅在实体硬件侧进行。固定叙事、动作教学、结果说明不是可交互对话，继续保留。
- 游戏 HUD 的“硬件麦克风已关”为只读设备状态，不可点击，不申请手机麦克风权限，不触发录音或聊天。
- G17、G17R、G22 只保留成绩/解锁信息、继续、再练和休息，底部为非交互安全提示。没有“是否保留记忆”、保留/丢弃按钮，也不跳到记忆确认页。
- 记忆在 App 管理端允许查看、删除，不允许修改；此项由 App 规格实现。游戏端不增加记忆编辑或详情操作。
- 本轮未定义闯关记忆的生成、自动保存或保存时机，不能将删除选择步骤解释成默认自动保存。
- G02B 充电禁练时返回器灵主页查看硬件状态；G23 仅陈述技能结果。关卡进度、首次技能解锁、已有技能、暂停快照、断连核对和安全门禁维持原规则。
- 14 张动作教学扩展状态已逐项审计，没有记忆留存选择或器灵对话入口，无需改图。
